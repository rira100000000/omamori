# Changelog

## 0.2.0 (2026-10-25)

### Breaking changes

- **There is no default reporter.** Choose one with `omamori init --reporter ...` (or `--reporter` on `omamori scan`). Without one, `omamori scan` stops and shows how to run `init`. An 0.1 config that only sets `api_key` keeps using Gemini, now with `gemini-3.8-flash`.
- `omamori init` takes the settings as flags (`--reporter`, `--reporter-model`, `--classifier`, `--classifier-model`, `--language`, `--ci`, `--force`) and requires `--reporter`. It no longer overwrites an existing `.omamorirc` unless `--force` is given.
- Without a classifier, all checks are now run by default (0.1 ran 6 main checks). The checks are now 35: `server_error_information_exposure` is merged into `overly_detailed_errors`, and `dependency_trojan_package` (malicious packages) is no longer judged by AI. Use bundler-audit (run by omamori) for known vulnerable versions, and a scanner with a malicious-package database (such as OSV-Scanner or GitHub dependency review) for malicious packages.
- Checks about something being absent (CSP and other security headers, production settings, two-factor authentication, password policy, audit logging) now ask whether the change weakens or removes an existing protection, instead of whether the application has it.

### Added

- **Classifier**: a fast decision model (TypeSafe Jev, OpenAI Decisions, or one on Ollama) checks each risk as a yes/no question, and only the flagged checks are sent to the reporter. Several risks are also asked as concrete sub-checks. The default threshold is 0.5.
- **Reporter choice**: any provider RubyLLM supports, or a Claude Code (`claude -p`) / Codex (`codex exec`) subscription. A fallback reporter (`reporter.fallback`) is asked when the reporter refuses or fails.
- `omamori doctor`: sends the configured classifier and reporters one small request each and says what is missing.
- `omamori scan --base REF`: scans the diff between REF and HEAD (what a pull request contains).
- CI configurations generated by `init --ci` / `ci-setup` pass the API keys your classifier and reporter need.
- An eval set (`evals/`) with AI-written cases, a holdout set, real security fixes from the GitHub Advisory Database, and ordinary commits for measuring false alarms.
- README sections on getting started and on setting omamori up with an AI agent.

### Fixed

- A reporter refusing to analyze content (Gemini sometimes refuses security analysis) was shown as "no risks". Refused or failed checks are now kept as flags, so nothing is silently passed.
- The `ci-setup` command was not recognized.
